Slide 10 appendix · Success metrics, risks & GTM

Every metric, every risk, and the plan that ships it.

Three screens. The metric tree — all sixteen metrics with definition, formula, instrumentation source and read cadence, and the chain that carries one tap on Add to Bag all the way up to slide 4's ₹504 Cr. The risk register in full, each risk tagged with the metric that trips first. And the go-to-market — four phases, who does what, and the readings that say expand, pause or kill. There are no targets anywhere on this page, and that is deliberate: Phase 0 is where the baselines come from, and the pre-launch power calculation is what sets the numbers.

AHow one tap on Add to Bag becomes ₹504 Cr

Left to right, nothing skipped. Each box is a real join in the data, not an analogy. Boxes 3 and 4 are the deck's existing funnel — Fabric Match does not touch them; it only changes how many taps enter at box 2.

The guardrail runs the other way. GMV kept after returns per view takes the returns off box 5 before it counts. A tap that becomes a return never completes this chain — it costs the reverse logistics, the resale margin and the shopper's next visit. That is the whole reason the primary metric is not allowed to be read on its own.

Tier 3 · Guardrailsthese must not move — and one of them is allowed to move only in one direction
Returns citing quality Orders returned citing quality or “not as described”, as a share of orders. quality-reason returns ÷ ordersexposed vs holdout Return reason codes on order_line, restricted to the quality / not-as-described set. Monthly — the return window sets the lag Converting more while returning more is fake GMV. This is the metric that decides whether a lift was real, and it is the one a mentor should ask about first.
Claim accuracy vs lab test Share of audited comparisons whose stated properties match an independent lab measurement of the garment. comparisons matching a lab measurement ÷ comparisons audited SKUs spot-bought from live inventory and measured for weight, stretch, drape and thickness; compared against the model's vector for that SKU. Per category, per model version A return rate cannot separate a wrong claim from a wrong choice — both look identical downstream. Only a direct audit can, which makes this the metric the guardrail above depends on to be attributable at all.
GMV kept after returns, per viewAppendix only Order value less returned value, per saved-item view. (orders × AOV − returned value) ÷ saved-item views order_line net of returns, over the same view denominator as ATB so the two are directly comparable. Monthly, exposed vs holdout The feature is designed to lose some sales. This is the single number that says whether losing them was worth it: a fall in add-to-bag is acceptable if and only if this holds. It is the metric that makes card 03's argument checkable rather than rhetorical.
Negative-verdict add-to-bagAppendix only Share of views carrying an unfavourable comparison that still end in an add-to-bag — paired with the return rate of exactly those orders. add-to-bags ÷ views with an unfavourable verdict Widget render event tagged with verdict polarity, joined to atb_click, then to returns on those order lines. Weekly, always as the pair The deterrence question made measurable. If warned shoppers buy anyway and return at the baseline rate, the warning was noise. If they buy less and the ones who do buy return far less, the deterred sales were returns we did not pay for. Card 03's entire argument reduces to this one pair of numbers.

Abstention rateAppendix only Share of eligible views where the model declines — “Can't tell from this listing”. abstentions ÷ eligible saved-item views Widget render event carrying the abstain state. Daily The only metric here that needs a ceiling and a floor. Too high and the feature is absent while appearing to be present. Too low and the confidence floor is not doing its job — abstention is what keeps claim accuracy honest, so a rate near zero is a failure of the guardrail, not a triumph of the model.
PDP latencyAppendix only Added time-to-interactive on the product page attributable to the widget. p95 PDP TTI, exposed − holdoutagainst the sub-2s page budget Real-user monitoring on the PDP, split by arm. Daily, alerting The comparison is personalised, so it cannot be fully precomputed per SKU. The garment vector is computed at ingest and cached; only the diff against the shopper's reference is computed at request. If that still misses the budget the widget degrades to absent — a slower page loses more than the comparison wins.
CoverageAppendix only Share of the catalogue with a usable property vector, weighted by saved-item volume rather than by SKU count. saved-item views of covered SKUs ÷ all saved-item views Property-vector table joined to save volume by SKU. Weekly, per category An unweighted coverage number flatters. 30% of SKUs might be 80% of saves, or 5% — you cannot tell without the weighting. The weighted number is what actually sets the shown rate, which makes it the Phase 2 gate.
Cost per profileAppendix only Marginal inference and storage cost of producing and refreshing one garment property vector. total inference + storage cost ÷ SKUs profiled ML platform billing attributed to the profiling job. Monthly The catalogue churns, so this is a recurring cost and not a one-off. It sets the ceiling on how far coverage can go, which makes it a constraint on the Phase 2 gate rather than a metric to optimise on its own.

What is deliberately not here: numbers. Every mitigation above names a mechanism and the metric that watches it, and none names a threshold. The thresholds come out of Phase 0 — the pre-launch audit sets the claim-accuracy floor, and the power calculation sets the detectable effect and the holdout duration. Inventing them now would be the one thing on this page a mentor could correctly call made up.

AFour phases, and what has to be true to leave each one

The order is not arbitrary. It runs from where we can check ourselves to where we cannot — private label first because Myntra owns the studio, the spec pack and the returns data, so claim accuracy is measurable end to end and no seller is exposed while the model is still unproven. Marketplace SKUs only after the model has earned it.

PhaseWhat shipsWhy in this orderExit gate
Phase 0
Instrument		 No shopper-facing change. Events, the holdout definition, the exposed/holdout assignment service, and a lab audit of a sampled slice of the catalogue. This is the honest reason the slide carries no targets. ATB, WPC₃₀, quality-return rate and time to decision have no clean saved-item baseline today. You cannot set a target against a number you have not measured. Baselines exist for all four. The audit yields a claim-accuracy reading per category. The power calculation sets n and the holdout duration.
Phase 1
One category		 Fabric Match on the PDP, private label only, one category. The full widget: verdict, sources under “Why this feel?”, and the abstain state. Myntra controls the clip, the spec pack and the returns data, so a wrong claim is traceable to its cause within days rather than through a seller. One category keeps the lab audit affordable and the vocabulary consistent. Measured claim accuracy holds at the floor Phase 0 set. Returns citing quality do not rise in exposed. GMV kept after returns per view is not down.
Phase 2
Marketplace		 Top marketplace SKUs by saved-item volume. Seller-portal clip upload, seller accuracy score, and a per-category coverage floor before the widget turns on there. Volume-weighted, so the shown rate moves as fast as it can for the effort spent. Sellers enter only once the accuracy score and the spot-buy audit exist to police them — the incentive has to be live before the surface is. Coverage clears the per-category floor. Seller-level claim accuracy holds. Escalations per 1,000 comparisons stay flat.
Phase 3
Beyond the PDP		 The comparison on the wishlist card itself, then the listing page and search. Last, because it is the highest-exposure surface and the lowest-context one. On the wishlist card the shopper has not asked the question yet, so a wrong claim there costs more and earns less. Everything above still holds at marketplace scale, and PDP latency has stayed inside budget across two quarters of catalogue churn.

CCommunications

Shopper side — no campaign. There is nothing to teach. Fabric Match is a sentence on a page the shopper is already reading, in the moment they are already asking the question. A campaign would be arguing for attention we already have, and it would promise a level of certainty the abstain state exists to avoid promising.

The only shopper-facing surfaces are the widget itself and the “Why this feel?” expander underneath it. Both are the product. Neither is marketing.

Seller side — an accuracy incentive, not a compliance ask. The message is merchandising, not policy: sellers whose spec packs are accurate and whose clips are clean get comparisons rendered on their listings, and a rendered comparison is conversion they did not pay for.

Framing it as a rule invites the minimum viable compliance that risk 6 describes. Framing it as a benefit that can be lost makes the accuracy score do the work.

The strongest thing about the shopper-side story is that it does not need one. Slide 6 measured shoppers spending a median 40 minutes and 3.1 attempts trying to answer this question themselves, and 74% saying one cleared doubt would have converted them that day. Demand for the answer is already established. What was missing was the answer.

DDecision gates — expand, pause, kill

If the question is “how would you know it failed?”, this is the answer. The readings are structural and they are fixed before launch; the thresholds attached to them come from Phase 0. Note that the second row is the one card 03 is about — a fall in add-to-bag is a passing reading, not a failing one, provided kept GMV holds.

What we readVerdictWhat we do about it
GMV kept after returns per view up, claim accuracy holding, quality returns flat Expand Next category, then the next surface. The mechanism worked and it did not cost anything to get.
Add to Bag down, but GMV kept after returns per view up Expand This is the designed outcome, and we say so out loud rather than hiding it. Deterred sales were heading for returns; negative-verdict add-to-bag and the return rate of those orders are the pair that proves it.
Served rate low, everything downstream unreadable Pause A coverage problem, not a product problem. Fix ingestion and re-read. Do not conclude anything about the idea from an experiment that did not reach people.
Claim accuracy below the floor the Phase 0 audit set Pause Raise the confidence floor, retrain, re-audit. Nothing ships while a claim is unreliable — an unreliable comparison damages more than a missing one.
Returns citing quality up in exposed Pause then kill Pause and check claim accuracy first — it separates a wrong claim from a wrong choice. If returns survive a claim-accuracy fix, the feature is causing the harm it exists to prevent, and it goes.
GMV kept after returns flat, with shown rate healthy and claim accuracy good Kill The cleanest kill, and the one worth stating plainly. The doubt was cleared, the comparison was right, it reached people — and the decision still did not close. That is risk 4 realised: fabric was not the binding constraint for this cohort. We would rather find that in one category than across the catalogue.
The thresholds are blank on purpose. Ask what number would kill it and the honest answer is that the structure above is fixed now and the numbers are set by the Phase 0 power calculation — before the exposed arm turns on, and pre-registered so they cannot be moved afterwards to fit a result. A kill criterion invented today, against a baseline that has not been measured, would be a number chosen to be survivable.
